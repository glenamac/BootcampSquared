# Example 1 — Suggesting preliminary qualitative codes

**Workflow title:**  
Interview excerpt coding support

**Success criterion:**  
The output suggests plausible preliminary codes with short justifications tied to the excerpt.

**Failure criterion:**  
The output overinterprets the excerpt, ignores uncertainty, or presents tentative codes as final conclusions.

**Human review rule:**  
A human researcher reviews every suggested code before it is added to the working codebook.

**Logging rule:**  
Save the excerpt ID, raw model output, prompt version, and final human-approved codes.

**Privacy or ethics note:**  
Do not send identifiable or sensitive participant text to a hosted model without appropriate protections. Use local/open models or de-identify first when needed.

# Example 2 — Classifying cases for follow-up review

**Workflow title:**  
Flagging survey responses for manual follow-up

**Success criterion:**  
The workflow reliably flags responses that match the criteria for manual review.

**Failure criterion:**  
The workflow misses clearly relevant cases or flags too many irrelevant cases to be practical.

**Human review rule:**  
A person reviews every flagged case before any action is taken.

**Logging rule:**  
Record the response ID, model output, flag status, and reason for flagging.

**Privacy or ethics note:**  
If the workflow affects people directly, keep a human in the loop and avoid fully automated decisions.
